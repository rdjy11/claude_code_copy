## 二、参与角色与任务分配

| 角色 | 谁 | 承担的任务 | 没有做的事 |
|------|-----|-----------|-----------|
| **编排/调度** | 主 Agent | 判定意图 → 读元规则 → 查路由表 → 选定专家 → 派发 → 汇总 → 写产出 → 对用户应答 | 不直接做技术取证 |
| **领域专家** | `bt-dtc`（子 Agent） | 全部技术取证：三层语料导航、比对、形成结论与依据清单 | 不写文件、不与用户交互、不派发他人 |

**任务分配原则**（来自设计）：专家**只读**，只负责「从语料中给出有出处的判断」；**输出形态与落盘由编排侧独占**。

### 为什么只派了 1 个专家

问题「DTC 老化条件」只命中路由表第 1 行（DTC 域），未命中其他域，因此无需并行多派。
**对照**：若提问是「0x19 响应超时 + DTC 状态字节怎么解读？」，则会同时命中第 1、2 行，触发 `bt-dtc` 与 `bt-uds` **并行派发**（该情形已在验证阶段实测通过）。

## 三、交互机制：怎么协作的

```
用户提问
   │
   ▼
主 Agent ──① 加载 Skill `basetech`（含路由表与三条工作流配方）
   │     ② 读 _index/meta-rules.md（判定是否涉及文档优先级）
   │     ③ 查 _index/by-domain/ 确认域索引存在
   │
   │  ── 判定：单域（DTC）／元规则不涉及（460/468/1103 均无关）
   │
   ├──④ 派发 ──▶ 子 Agent `bt-dtc`（独立上下文）
   │                  │  自主执行三层导航：
   │                  │   L0 读 _index/by-domain/bt-dtc.md 圈定候选编号
   │                  │   L1 Grep SWRS_DHU_需求清单.md 取摘要
   │                  │   L2 读 Basetech知识库语料/ 相关卷取原文
   │                  │
   │   ◀──⑤ hand-back ──┘  返回完整报告（结论 + 依据清单 + 推断 + 未覆盖声明）
   │
   ├──⑥ 原样汇总，写入 _out/qa-20260930-234601.md
   └──⑦ 对用户给出摘要（路由说明 + 核心结论）
```

**关键交互特征**：

1. **子 Agent 拿到的是「域专家身份 + 定位方法」，不是具体指令**——主 Agent 只说「查 DTC 老化条件」，如何找到、读哪些卷、如何判断，全由子 Agent 按 `bt-dtc.md` 的正文自主决定。这是「专家」而非「工具调用」的本质区别。
2. **子 Agent 拥有独立上下文**，因此它 15 次读文件 + 19 次 Grep 的过程**不占用主 Agent 上下文**，只把最终报告交回。
3. **单向 hand-back**：子 Agent 不能向用户提问，也不能再派发其他 Agent，只能返回报告。信息不足时须在报告中声明，由主 Agent 决定是否追问用户。

这类「区分取证强度」的自律行为，来自 `bt-dtc.md` 正文中「引用层级必须说清」与「无编号支撑必须标注推断」的要求。

## 六、观察与偏差（如实记录）

### 6.1 `basetech-orchestrator` 未被调用

设计原意是由 `basetech-orchestrator` 这个 subagent 承担编排。**实际执行中，编排由主 Agent 直接完成**，未派发编排者。

- **原因推测**：主 Agent 已加载 Skill（含路由表），顺势自行完成了编排，未再中转一层。
- **影响**：功能上无损失，且**更优**——主 Agent 可与用户交互，而编排者是 subagent、无法向用户提问（这正是设计文档中列为风险的一条）。少一层中转也更快更省。
- **建议**：可以考虑把设计改为「主 Agent 编排 + 编排者仅用于无人值守场景」，或保留编排者但明确它只在被显式点名时使用。属待议事项。

### 6.2 元规则文件路径曾被猜错

主 Agent 读取时用的是 `<项目根>/meta-rules.md`，而正确路径是 `<项目根>/_index/meta-rules.md`（丢了一层 `_index`）。

- **当时之所以没报错**：项目根下恰好存在一份**同类残留文件**（构建脚本早期版本误写所致），内容恰好一致，因此「读错了但读对了」。
- **已处理**：① 删除根目录残留文件；② 在 `SKILL.md` 与 `basetech-orchestrator.md` 中把该路径标为完整绝对路径，并明确提示「路径含 `_index` 子目录，项目根下没有该文件」。
- **教训**：这类「错路径被同名残留掩盖」的问题不会自我暴露，需要靠清理与显式路径来防。
