# 工作流：生成（gen）

**用途**：按 SWRS 既有格式，生成新的需求条目（如为某 ECU 补充诊断需求、为某功能补写 shall 句）。

## 步骤

1. 读 `_index/meta-rules.md`——若涉及文档优先级，先由编排者判定
2. 按 `SKILL.md` 路由表判定涉及的领域
3. 派发 **1–2 个**相关专家（跨域时并行派发全部相关专家）
4. 由专家**先取同域既有条目的格式与措辞**作为样板
5. 汇总为新增需求条目，写入产出文件

## 硬约束

- **必须复用文档既有格式**，逐条包含以下字段（缺一不可）：

```markdown
### <编号占位> — <标题>
- 版本：<vN，新增建议 v1>
- 验证方式：<Test / Analysis / Inspection 三选一>
- 适用：<AUTOSAR 版本 或「通用」>
- <shall 句>
```

- **必须是 shall 句式**（`shall` / `shall not`）。不得写成「建议」「应该」「需要」这类非规范性表述；
- 每条**必须标注**：`> 新增条目，需求编号待人工确认`；
- 编号占位统一写 `<新增>`，**不得自行编造编号**——编号由人工分配；
- 生成的内容必须有同域既有需求作为依据（专家需给出参照的需求编号），不得凭空发明技术要求；
- 若生成意图超出文档覆盖范围，明确说明「文档未覆盖，无法生成」并说明缺什么。

## 产出格式

写入 `_out/gen-<时间戳>.md`：

```
# 需求生成：<意图摘要>
- 涉及领域：<专家列表>
- 参照依据：需求 <编号>《<标题>》等

## 新增需求条目
### <新增> — <标题>
- 版本：v1
- 验证方式：<...>
- 适用：<...>
- <shall 句>
> 新增条目，需求编号待人工确认

（多条依次列出）

## 需要人工确认的事项
- 编号分配
- <其他：如取值范围、阈值需标定确认等>
```

## 与问答工作流的区别

问答是「**读**已有的要求」；生成是「**写**新的要求」。因此生成必须以既有条目为样板与依据，且**不得编造编号**——编号永远留给人工分配。
