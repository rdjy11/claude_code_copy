### 2537 — ClearDiagnosticInformation (14) - groupOfDTCSpecific DTC
- 版本：v3 ｜ 验证方式：Test ｜ 适用：通用 ｜ Legacy ID：76497v2

It shall be possible to remove specific DTCs. If the ECU is not emission related, the service ClearDiagnosticInformation with the data parameter groupOfDTC set to a value of any specific DTC shall be supported by the ECU in all sessions where the ECU supports the service ClearDiagnosticInformation. If the ECU is emission related, the service ClearDiagnosticInformation with the data parameter groupOfDTC set to a value of a “calibration DTC” shall be supported by the ECU in all sessions where the ECU supports the service ClearDiagnosticInformation. A “calibration DTC” is a non-emission related DTC that indicates that a specific action (e. g. request a diagnostic service for initiating or calibrating a function controlled by the ECU) that must be performed as a part of the car manufacturing process has not yet been performed and that shall be cleared (by the diagnostic service ClearDiagnosticInformation with the data parameter groupOfDTC set to a value of the “calibration DTC”) as soon as the action has been completed. This requirement is only applicable if the ECU support “calibration DTCs” (one or more). If the ECU is emission related, the service ClearDiagnosticInformation with the data parameter groupOfDTC set to a value a non-emission related DTC, other than a “calibration DTC”, is allowed to be supported by the ECU in all sessions where the ECU supports the service ClearDiagnosticInformation. If the ECU is emission related, the service ClearDiagnosticInformation with the data parameter groupOfDTC set to a value of an emission related DTC is not allowed to be supported by the ECU.

P2*Server_min is specified differently for final response and pending response. For final response it shall be as short as possible to allow good timing performance. For pending response it must be a suitable value so that a server do not significantly increase bus load by consecutive pending responses.
