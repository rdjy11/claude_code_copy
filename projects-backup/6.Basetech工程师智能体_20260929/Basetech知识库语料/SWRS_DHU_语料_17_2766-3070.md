The Software Download concept provides a means for a tester to send multiple bytes of data toan ECU.4.6.1.1.4 What is the purpose of this documentThis specification is the top document of the SoftWare DownLoad (SWDL) concept. Thespecification describes the background and the non-data link dependent requirements for abootloader as well as the programming sequences used for software download. For details onspecific protocols, data links, components and algorithms, please read the respectivelydocuments. This specification is intended to provide guidance and requirements to architects, systemdesigners, application developers, and ECU suppliers. Adherence to the specificationscontained within this document is required to ensure compatibility within the corporate productline from vehicle to vehicle, model year to model year and maintain compatibility with theindustry driven standards. Important to understand is that this specification only specifies the general non network specificrequirements for a bootloader.4.6.1.1.5 IntroductionElectronic Control Units (ECUs) have demonstrated continued increase in feature, count,memory size, I/O circuit count, and part number complexity. All areas of the vehicleelectrical/electronic system are affected. Electronic Control Units are experiencing late andfrequent changes many of which affect software. These trends will undoubtedly continue intothe foreseeable future. There is a need to reduce vehicle build and service complexity, reduce ECU suppliercomplexity, and allow for maximum flexibility in software design by establishing designs andprocedures providing the ability to configure and program ECUs in assembly and in service. Configuration and module programming will allow module design and release activities tominimize part complexity, economies of scale and allow bookshelf software to be utilized. By having software download possibility in all ECUs with complex functionality the cost of correcting software errors is significantly reduced and new functions can be added after production. The software download functionality is used both in the production line to customize the hardware for the specific car and in workshops to correct errors or improve functions. The software download concept is based on a primary bootloader that is fixed in the ECU and always executed at power on before the application is started and a secondary bootloader, including non-volatile memory programming routines that is downloaded before downloading the rest of the applications and configuration files. Important is to reduce the download time as much as possible to enable a convenient user experience and reduced assembly and workshop time/cost spent on the programming phase. Important technologies such as compression and delta encoding of data reduce the software size as well as using available bandwidth by parallel download of multiple ECUs is therefore motivated.4.6.1.2 General Bootloader requirements4.6.1.2.1 Validation of ECU software(s) - Complete and CompatibleThe bootloader shall at every start (initiation phase) and upon request from the diagnostic tester (routineldentifier(Check Complete & Compatible), check if the ECU software(s) is complete and compatible before starting execution of the application. The purpose of the "Complete & Compatible Check" is to ensure that the expected software parts are programmed successfully and are valid (complete), e. g. to detect if any part of the software is missing, broken (partly present/downloaded) or has been altered. This check shall also decide whether the combination of stored software parts are compatible to each other. The compatible check can be done in many different ways and will be different from case to case. It is either exclusively handled by the bootloader or by using a call-out to a function block that is part of the application. The compatibility check is only performed once the complete check has passed successfully. The Complete & Compatible check shall be implemented in such a way that it must not be updated for each new or modified data file. ![](images/9ebcfe15a0e599e0dca2a23c00bac5d8e5c9215de6dacc7c729e30f522c83551. jpg) Page No1333(1572) The bootloader shall at every start check if the ECU software(s) is complete and compatible before starting execution of the application.
