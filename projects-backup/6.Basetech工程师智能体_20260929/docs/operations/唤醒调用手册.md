## 一、角色对应表

### 1.1 总入口（1 个）

| 名称 | 中文名 | 职责 | 典型问法 |
|------|--------|------|---------|
| `basetech-orchestrator` | Basetech 编排者 | 判定你要做什么（问答/评审/生成），自动分派领域专家并把结果汇总 | 「Basetech 问答：……」<br>「评审这份材料：……」<br>「生成一条……需求」 |

## 二、启动前提（必须做对，否则全部不可用）

本智能体的全部角色都定义在**项目目录**下。**必须先从项目目录启动**，否则它们不会被加载。

```bash
cd "C:/Users/pc/claude_code_copy/projects/6.Basetech工程师智能体_20260929"
claude
```

如果你从别的目录（例如 `C:\Users\pc`）启动，智能体会**静默不生效**——表现为提问后得到通用回答，看不到需求编号出处。

**自检方法**：启动后随便问一句「Basetech 问答：DTC 老化条件是什么？」，正常应给出带需求编号的答案并生成 `_out/qa-*.md` 文件。

## 三、唤醒方式

### 3.1 推荐：直接说要点（自动分派）

不需要记任何名字，把你的问题和意图说清楚即可：

```
Basetech 问答：SecurityAccess 的时序要求是什么？
```

```
Basetech 评审：请评审下面这份 ECU 诊断实现说明，找出与 SWRS 不符的地方
<把你的材料贴在这里>
```

```
Basetech 生成：为某 ECU 生成一条关于周期读取 DID 的需求
```

### 3.2 强制点名（想指定视角时）

当你知道该问哪个领域，或自动分派结果不满意时，直接点名：

```
用 bt-dtc 专家：DTC 老化条件是什么？
```

```
用 bt-nm 专家回答：PNC 请求的转发时序
```

### 3.3 什么情况会自动分派、什么情况建议点名

| 情况 | 建议 |
|------|------|
| 问题明显属于某一个域 | 自动分派即可 |
| 问题横跨多个域（如「刷写失败后 DTC 怎么置位」） | 自动分派——编排者会**并行派多个专家**再汇总 |
| 想确保从某个特定域看问题 | 点名 |
| 上一次分派错了 | 点名纠正，并可反馈给我 |

## 四、三条工作流用法

### 4.1 问答

**怎么问**：一句话说清要查什么。越具体越好（带上服务号、参数名、ECU 类型会更准）。

**你会得到**：结论 + 需求编号出处（编号、标题、语料卷）+ 原文引用。若文档没写，它会明确说「文档未覆盖」，**不会编造编号**。

**产出**：`_out/qa-<时间戳>.md`

### 4.2 评审

**怎么给材料**：直接把文本贴进对话即可（也可以给文件路径）。

**你会得到**一份报告，含四部分：
- 统计行：符合 X ｜ 不符合 Y ｜ 无法判定 Z
- 差距清单（按严重度降序）：`编号｜要求摘要｜材料现状｜判定｜依据原文`
- 跨域冲突
- 无法判定项及原因（需要你补什么信息）

**产出**：`_out/review-<时间戳>.md`

**注意**：判定只有三值——符合 / 不符合 / **无法判定**。若材料信息不足，它会归入「无法判定」而不是猜，这是刻意设计。

### 4.3 生成

**怎么提需求**：说明「要为谁、生成什么类型的要求」。

**你会得到**：符合 SWRS 既有格式的新需求条目（编号占位、版本、验证方式、适用版本、shall 句），并标注「新增条目，需求编号待人工确认」。

**重要**：它**不会编造需求编号**——编号永远留给你人工分配。生成内容必须挂出参照的既有需求编号。

**产出**：`_out/gen-<时间戳>.md`

## 五、可直接复制的样例

**问答**
```
Basetech 问答：非编程会话下 P2Server_max 是多少？
```

**问答（跨域）**
```
Basetech 问答：ReadDTCInformation（0x19）的响应超时是多少？读回的 DTC 状态字节怎么解读？
```

**评审**
```
Basetech 评审：请评审下面这份 ECU 基础技术实现说明，找出与 SWRS 不符或遗漏的地方。

1. 诊断采用 UDS，服务器 P2 最大响应时间统一取 100 ms。
2. SecurityAccess（0x27）在默认会话与编程会话均支持。
3. 支持 ReadDTCInformation（0x19）并返回 DTC 状态字节。
4. DTC 在确认后即存储，不涉及计数与清除机制。
```

**生成**
```
Basetech 生成：为某 ECU 生成一条关于「支持周期读取数据标识符」的需求条目。
```

## 六、故障排查

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 提问后回答很泛，看不到需求编号 | 启动目录不对，智能体未加载 | 按第二节 `cd` 到项目目录后重启 |
| 指名专家但对方说「找不到」 | 同上 | 同上 |
| 分派到了不合适的专家 | 问题表述有歧义 | 点名指定专家；或把问题说得更具体 |
| 回答「文档未覆盖」 | 该内容确实不在 SWRS 范围内（如云端协议、跨车通信） | 正常行为，请查其他资料 |
| 回答中有「推断」字样 | 该部分无需求编号支撑 | 请人工复核后再采纳 |
| 找不到产出文件 | 看 `_out/` 目录，文件名形如 `qa-20260930-143022.md` | 确认启动目录正确 |
| 引用的编号查不到 | **属异常，请反馈** | 智能体被要求禁止编造编号，出现即缺陷 |
| 评审报告缺少「统计行」或「跨域冲突」节 | 属异常，报告未按格式产出 | 请反馈 |
