# 问答：DTC 老化（aging）条件是什么？

> 工作流：**问答**（`.claude/skills/basetech/jobs/qa.md`）
> 路由：DTC / 老化 → 专家 `bt-dtc`（单域，未触发元规则 460/468/1103）
> 时间：2026-09-30 23:46
> 引用层级声明：本节结论均取证至 **L2 语料正文**；凡仅取自 L1 清单者另行注明。

---

**结论**：

1. **进入条件**——当某个 DTC 的**老化计数器达到该 DTC 被标定的 `agedDTCLimit`** 时，该 DTC 即判为 aged。老化计数器**只能是 Operation Cycle Counter #2 或 #5（OCC2 / OCC5）**，由实现方指定用哪一个；`agedDTCLimit` 取值范围 **[1, 255]**。
2. **阈值标定原则**——`agedDTCLimit` 应标定到"故障已长时间未被检出、以致很可能不会再发生/再被检出"的时刻，典型即该故障**已自愈（self-healed）或被误检**。
3. **emission related DTC 的特殊规则**——可**同时使用 OCC2 与 OCC5** 两个计数器，此时须**两个计数器都达到 `agedDTCLimit`** 才判 aged。
4. **老化后的动作**——
   - *AUTOSAR 4.0.x*：**不清除** DTC 记录，仅复位个别状态位与状态指示位；SI30 bit3 = AgedDTC **置 1**，该位在 **aged DTC 再次发生（reoccurs）时复位为 0**。
   - *AUTOSAR 4.1+*：**清除全部 snapshot data 与 extended data records**，全部状态位一并清除，**唯独 `testFailedSinceLastClear` 保持原状态**；SI30 bit3 **恒为 0**。
5. **不要混淆的三个阈值**——aging 用 **OCC2/OCC5 + agedDTCLimit**；confirmedDTC 用 **OCC6 + confirmedDTCLimit（[1,15]）**；unconfirmed 用 **FDC10 达到 [unconfirmedDTCLimit, +127]**。**OCC6 不是老化计数器**。
6. **与长期存储溢出的关系**——aged DTC 在存储淘汰中处**优先级 3（最低）**，同为最低优先级时按 **OCC2 值最大者先清**；若因存储溢出导致该 DTC **未分配老化计数器（OCC2/OCC5）**，则 confirmedDTC 位不得再置 1 且须清 0。

**推断**：

1. **推断**——OCC5 按 2115 原文仅对 emission related DTC 实现，故非排放 DTC 的老化计数器实际只能是 OCC2。此为 1812 + 2115 的组合推断，文档未以单条 shall 明写。
2. **推断**——OCC2 的递增触发点是"本操作周期内 FDC10 达到 -128"，而 DTC 测试被 TRC 抑制时 FDC10 不更新（1824），故频繁进入低电压/模式切换抑制的车辆，老化计数推进会变慢、aging 时间被拉长。
3. **推断**——1814 中 aged 记录优先级最低，意味着老化的工程含义不止"信息复位"，还包括"存储紧张时优先被挤掉"。
4. **推断**——4.1+ 下 SI30 bit3 恒为 0（2134）且 1813 变为 Not Applicable，表明 4.1+ 不再用 AgedDTC 标志位表达老化状态，改为直接清记录。

**文档未覆盖**：

- **pendingDTC 的 DHU 特有置位/清除条件**——2126 仅要求"按 UDS 支持"，本 SWRS 未定义条件。
- **以 "healing / 自愈" 命名的独立需求条款**——语料全文无此命名的 shall 条目，仅 1804 出现 "self-healed" 一词。
- **通用 DTC 的 `agedDTCLimit` 具体数值**——1804 只给标定原则（Verification Method: Test），通用值需查 [Data 12] General Diagnostic Guideline。
- **"哪些 DTC 用 OCC2 / 哪些用 OCC5" 的完整映射**——1812 交由 implementer 指定，文档未给全量清单。
