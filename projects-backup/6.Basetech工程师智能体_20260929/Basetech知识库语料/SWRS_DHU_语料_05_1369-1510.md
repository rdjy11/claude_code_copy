### 1377 — Active Request Session
- 版本：v3 ｜ 验证方式：Test ｜ 适用：通用 ｜ Legacy ID：347883v2

To define the term Active Request Session, ARS. Active Request Session, ARS shall be implemented according to the following definition. The ARS is a state bound to single IP links. Whenever an IP_activity message is received, with ACTION-field = AVAILABLE | REQUEST_RG_X an ARS shall be set for the IP link. The ARS exist as long as new IP_activity messages are received from the same IP link within the time defined by Request_monitoring_timeout. ### 1378 — ARS timers

To define usage of the monitoring timers in the LM module. The LM module shall implement one timer for each Active Request Session, ARS. This timer shall assume the value given by Request_monitoring_timeout. The timer shall start when the LM module has registered an ARS upon reception of the IP_activity message. Each time LM receives an IP_activity message it shall restart the interface-specific timer and when an interface is declared dead its timer shall stop. ### 1391 — Firewalling rules
- 版本：v8 ｜ 验证方式：Analysis ｜ 适用：通用 ｜ Legacy ID：55074v6

To ensure that only desired IP traffic is allowed into and out of the in-car network. The ECU shall implement a firewall with a firewall rules ensuring that only desired IP traffic is allowed to the ECU itself and between different ip interfaces connected to the ECU. It shall be possible to configure firewall rules based on information such as transport protocol, source address, destination address, source port and destination port to control ingress and egress traffic. The default state of the firewall shall be to block all traffic not explicitly allowed by firewall rules. All IP IPv4/v6 traffic to/from and through the ECU shall be inspected by a stateful firewall operating on OSI level 2-4. Firewalls should be configured to: Deny ipv4 and ipv6 network traffic by default and fail secure. Protect and inspect ip4 and ipv6 traffic according to set firewall rules. Block or protect from network packets and patterns typically used to execute ‘denial of service’ attacks such as Ping flood and SYN attacks. Implement ingress and egress filtering, such as denying incoming and outgoing traffic where the source address is known to have been spoofed. Source ip address of traffic leaving the firewall must only come from vehicle internal networks and interfaces. Incoming off board traffic must not have a source address of internal vehicle ip networks, localhost, network address or broadcast addresses. Packets that are not possible reassemble to inspect as a whole due to fragmentation shall be discardedIt must be possible to update the firewall configurations (settings and rule set etc.) remotely from the cloud. UDP traffic direction shall be inspected and return traffic shall only be allowed in a configurable timeframe to create a TCP session like behavior. Only expected ICMP reply messages shall be allowed when an outbound ICMP message is sent. E. g Echo request will allow an ICMP reply message in the reverse direction.
